# 歌单队列拼贴

日期：2026-09-30  
状态：待实现  
来源：把 [folia-major](https://github.com/chthollyphile/folia-major) 的队列拼贴（Lattice）接到本仓库，作为专门导出歌单视频的播放器。

本文件只覆盖第 1 步：拼贴画面。第 2 步（若干音频收成歌单）和第 3 步（导出命令）另写规格。方向已经定下，写在文末，避免和第 1 步混在一次实现里。

## 目标

新增 Composition `PlaylistPlayer`，1920×1080、30fps。一份有序歌单从头播到尾：海报墙一直在，当前这首在中央展开并显示当前句歌词，切歌时镜头飞到下一首最近的海报并展开，周围海报让开。

几何、重复、展开重排、镜头时间和歌词填充按 Folia 的计算来。画面用 Remotion 的帧驱动，能稳定渲染。

## 非目标

- 不接 Folia 的 Stage API、歌词接口或当前音频。歌单来自你给出的若干音频，由第 2 步按现有单曲备料处理。
- 不搬 Folia 的页面组件、拖拽、键盘、Pixi 画布、framer-motion 和状态库。
- 不画播放控件：暂停、进度、聚焦、关灯、点击别的海报放大。
- 不做入场波浪。开场墙面已经就位。
- 不改 `AMLLPlayer` 和 `AlbumPlayer`。
- 第 1 步不改备料 CLI，也不改导出 CLI。

## 架构

`PlaylistPlayer` 与现有两个播放器并列，注册在 `src/Root.tsx`。数据全部走 Composition props。

三层纯计算，再按帧绘制：

1. **墙面几何。** 从 Folia 搬 12×8 块版式、镜像，以及某个槽展开成 6×6 后整块的重排表。歌单在墙上无限重复。展开只重排它所在的那一块。
2. **时间。** 帧决定当前曲目、镜头和每张海报的矩形。格子 128、间距 8、缩放 0.76。缩放在整段成片里不变。
3. **绘制。** 只画视野内的海报。未展开的是封面、序号、歌名和歌手。正在展开且弹簧未停时同样只显示歌名和歌手。弹簧停稳后，当前海报再加上当前句歌词。四周加暗角。

音频按曲目首尾相接，各自一段 `Sequence` + `Audio`，不交叉淡化，不先拼成一个文件。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/Playlist/lattice/blockTemplates.ts`、`blockReflows.ts` | 版式、镜像、展开重排表。数据从 Folia 原样搬。 |
| `src/Playlist/lattice/layout.ts` | 歌单如何重复、视野内有哪些海报、某序号离镜头中心最近的一张、展开后的目标矩形。 |
| `src/Playlist/lattice/motion.ts` | 帧换成镜头和插值后的矩形。 |
| `src/Playlist/lattice/lyrics.ts` | 当前句换行和逐字填充。输入是现有 `LyricLine`。 |
| `src/Playlist/Poster.tsx` | 一张海报。 |
| `src/Playlist/Main.tsx` | 音频、镜头、视野内海报、暗角。 |
| `schema` / `calculateMetadata` / `constants` / `Root.tsx` | `PLAYLIST_COMPOSITION_ID = "PlaylistPlayer"`。props 是 `{ tracks }`，至少一首，每首字段与单曲 `trackSchema` 相同。 |

`trackSchema` 上的 `backgroundMotion` 本播放器不读。

曲目身份用队列序号，不用歌名或歌曲 id。同一首出现两次就是两张海报，墙再把整份列表重复铺满。

## 镜头和展开

常量：

- 格子 `cellSize = 128`，间距 `gap = 8`，缩放 `scale = 0.76`。
- 视野外再保留 500px，单帧最多画 400 张海报。
- 镜头飞行 0.42 秒，三次贝塞尔 `[0.22, 1, 0.36, 1]`。
- 海报位置和大小用弹簧：质量 1、刚度 300、阻尼 34，从静止起步。
- 歌词出现：弹簧后的宽高与目标相差都不到 1px，或切歌已过 1 秒，取先到的那个时刻。开场视为已经停稳。

开场（第 0 帧）不飞行。在 `repeat (0, 0)` 的格子里，取队列序号 0、`cellSlot` 最小的那张海报，用它展开后的 6×6 矩形，按缩放 0.76 放到 1920×1080 正中。这一帧就显示歌词。

切歌的第一帧同时做两件事：镜头开始飞向当前视野中心附近、下一首的那张海报；那一块开始展开，上一块弹簧收回版式原位。飞行和弹簧都从这一帧的已有矩形起算。成片在动画中途结束，就停在那一帧，不补帧。

## 海报

每张海报封面铺满。左上角角标是标记，不是按钮：

- 其他海报：两位序号，从 `01` 起。
- 当前海报：`正在播放 · 01` 这种形式，序号同样两位。

未展开，以及展开弹簧未停时：底部歌名和歌手。弹簧停稳且是当前海报：歌名、歌手、当前句歌词。字用现有 `playerFontFamily`，白色。

底部遮罩用夜间的黑色渐变，保证字能看清。未展开：自上而下，34% 处 5% 黑、56% 处 24% 黑、底部 92% 黑。展开后改成两层：自下而上 0% 处 86% 黑、14% 处 62% 黑、30% 处 26% 黑、46% 处全透明；再加上自左向右 88% 黑到 52% 处 50% 黑、再到右侧 8% 黑。

暗角是铺在画面最上层的径向渐变：中心到 78% 透明，边缘 `rgba(0, 0, 0, 0.52)`。不做日间模式。

## 歌词

字号按海报内容区的固定预算计算，不随这一句的长短变化。换行按词边界；一个词放不下时按字素切开。

填充：

- 词的起止时间彼此错开：按当前时间填充，时间落在某个词中间时，该词按已经过去的比例填充。
- 这一句没有彼此错开的逐字时间（没有词，或所有词的起止都等于整行）：行开始时整句出现。备料不另造逐字时间。

译文用 `LyricLine.translatedLyric`。有非空译文时，主句下最多两行；没有则不画。罗马音不画。

歌词时钟用这首内部的秒数。`calculateMetadata` 若沿用单曲解析读了歌词文件，偏移写进行时间后把 `lyricOffsetMs` 置 0。props 里已经带好 `lyricLines` 时，行时间保持原样。

## 数据流

```text
props.tracks
  → calculatePlaylistMetadata
       总帧数 = 各首可播放帧数相加（沿用 trackDurationInFrames）
       时长和 lyricLines 已经在 props 上时，不读音频文件，也不读歌词文件
  → PlaylistPlayer
       帧 → 当前序号、这首内部的秒数
       每首一段 Sequence + Audio，帧段首尾相接，中间没有空帧
       曲目 → 海报（序号、歌名、歌手、封面）
       motion(帧) → 镜头、每张海报这一帧的矩形
       当前海报用内部毫秒数取当前句
```

可播放时长是 `audioEndInSeconds ?? durationInSeconds` 减去 `audioOffsetInSeconds`，与单曲相同。

第 1 步没有歌单配置文件。Studio 默认 props 把现有的 `OneLastKiss` 放两遍，用来看到墙、展开和一次切歌。这两首若还没有内嵌 `lyricLines`，默认入口可以走现有单曲解析把时长和歌词行补上。这只为 Studio 能打开，不是歌单校验。

封面和音频地址沿用现有的 `staticFile` 解析。

## 校验

画面不校验，也不做缺封面纯色、缺歌词占位、把 0 时长收成 1 帧。歌单要齐（每首有音频、正的可播放时长、封面、歌名、歌手、歌词行）由第 2 步备料拦截。第 1 步的测试和默认 props 只用已经齐的曲目。

封面或音频文件本身损坏时，跟现有播放器一样，让 Remotion 的加载失败冒出来。

## 测试

只测纯计算，不跑渲染。夹具都是齐全曲目。

- **墙面。** 一块里各槽的格子面积之和等于 12×8，两两不重叠。像素矩形之间留出 8px 间距。任一槽展开成 6×6 后，这一块的格子仍然铺满且不重叠。同一歌名出现两次仍是两个序号。给定镜头中心，返回指定序号最近的那张。
- **时间。** 第 0 帧镜头已经停在第一首展开海报的正中，没有从别处飞来。切歌那一帧镜头仍在切歌前的位置；过 0.42 秒后到达目标。0.21 秒时的进度大于线性的一半（缓出）。切歌后 0.2 秒，正在移动的海报矩形落在原位和目标位之间。三首帧段首尾相接，总帧数等于各首之和，每首内部秒数从该首起点重计。
- **歌词。** 时间落在第二个词中间时，第一个词已填满，第二个词按比例填充。词的起止等于整行时，行一开始就整句出现。没有译文不产生译文行；有译文时不超过两行。
- **元数据。** props 已有时长和 `lyricLines` 时，不读音频或歌词文件，总帧数等于各首之和。
